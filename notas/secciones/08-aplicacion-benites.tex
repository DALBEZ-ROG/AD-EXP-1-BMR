PresustentacionesAWPS ya tenía una API REST con JWT y Swagger; Angular la consulta cada 15 segundos para mostrar el estado de una solicitud. Lo nuevo fue ofrecer esa misma consulta por SOAP con Spring Web Services: escribimos el contrato en XSD, el WSDL se publica en \texttt{/ws/estado.wsdl} y la operación \texttt{ConsultarEstadoSolicitud} llama al mismo \texttt{EstadoConsultaService} que usa el REST, así que la lógica no se duplicó. Si la solicitud no existe, el SOAP responde con un Fault de cliente. Al probarlo vimos que el REST devolvía \texttt{200} con datos casi vacíos en ese caso, y lo cambiamos a \texttt{404}.

Para comparar, medimos la misma consulta 200 veces con cada estilo en la misma PC. La respuesta SOAP pesó 703 bytes contra 252 del JSON, 2,8 veces más, y la petición SOAP también lleva 308 bytes de sobre. En tiempo, SOAP tardó en promedio 3,78 ms y REST 2,99 ms. Son números de una sola máquina y sin red, pero muestran la tendencia: para el \emph{polling} del front conviene REST, y SOAP queda para cuando otro sistema necesite un contrato formal.
